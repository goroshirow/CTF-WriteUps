# func-array

## / Overview

Out-of-Bounds Read

## / Writeup

プログラムのコアとなる脆弱性は `vuln` 関数内に存在します。
```c
unsigned int choice;
printf("Select an alpaca function index: ");
scanf("%u", &choice);

alpaca_functions[choice]();
```

ここで `alpaca_functions` は要素数3の関数ポインタ配列ですが、ユーザー入力である `choice` が3未満であるかどうかのチェックが行われていません。そのため、3以上の数値を入力すると、配列のために確保されたスタック領域の外側にあるメモリデータを関数ポインタとして読み込み、実行してしまいます。

次に `main` 関数の構造に注目します。

```c
int main() {
    // --snip--
    vuln();
    win();
    return 0;
}
```

`main`から`vuln`を呼び出す際、CPUは`vuln`の処理が終わった後にリターンアドレスをスタック上に保存します。今回のコードでは、`vuln`の直後の処理、すなわち`win`関数を呼び出す命令のアドレスがリターンアドレスとしてスタックに積まれます。

通常であれば、`vuln`の末尾にある`exit(0);`によってプログラムが終了してしまうため、このリターンアドレスが使われて`win`が実行されることはありません。

しかし、スタックのメモリレイアウトを利用することでこれを突破できます。
ローカル変数である `alpaca_functions` 配列からアドレスが増える方向へ読み進めると、先ほど保存されたリターンアドレスが存在します。今回は`alpaca_functions`の先頭アドレスから `+40バイト` の位置に、このリターンアドレスが配置されていました。

```
高位アドレス
|-------------------|
| リターンアドレス    | <- vuln()終了後に戻る main() 内のアドレス [rbp + 0x08]
|-------------------|
| 保存された RBP     | <- 呼び出し元のベースポインタ [rbp + 0x00]
|-------------------|
| Stack Canary      | <- セキュリティ機構 [rbp - 0x08] 
|-------------------|
| alpaca_funcs[2]   | <- 配列の3番目 [rbp - 0x10]
|-------------------|
| alpaca_funcs[1]   | <- 配列の2番目 [rbp - 0x18]
|-------------------|
| alpaca_funcs[0]   | <- 配列の先頭 [rbp - 0x20]
低位アドレス
```

したがって、入力として `5` を与えると以下の事象が発生します。

1. `alpaca_functions[5]` が参照される。
2. その参照先は、スタックに保存されていた `vuln` のリターンアドレスと一致する。
3. リターンアドレスには `win` を呼び出す命令のアドレスが入っている。
4. `alpaca_functions[5]()` が実行されることで、`exit(0)` に到達する前に強制的に `win` 関数へジャンプする。

結果として `win` 内の `system("/bin/sh");` が実行され、シェルを獲得してクリアとなります。

ちなみに`gdb`で`vuln`をディスアセンブルした結果は次のようになっています．

```nasm
(gdb) disas vuln
Dump of assembler code for function vuln:
   0x0000000000401257 <+0>:     endbr64
   0x000000000040125b <+4>:     push   rbp
   0x000000000040125c <+5>:     mov    rbp,rsp
   0x000000000040125f <+8>:     sub    rsp,0x30
   # --snip--
   0x00000000004012a7 <+80>:    lea    rax,[rbp-0x24]
   0x00000000004012ab <+84>:    mov    rsi,rax
   0x00000000004012ae <+87>:    lea    rax,[rip+0xde5]        # 0x40209a
   0x00000000004012b5 <+94>:    mov    rdi,rax
   0x00000000004012b8 <+97>:    mov    eax,0x0
   0x00000000004012bd <+102>:   call   0x4010d0 <__isoc99_scanf@plt>
   0x00000000004012c2 <+107>:   mov    eax,DWORD PTR [rbp-0x24]
   0x00000000004012c5 <+110>:   mov    eax,eax
   0x00000000004012c7 <+112>:   mov    rdx,QWORD PTR [rbp+rax*8-0x20]
   0x00000000004012cc <+117>:   mov    eax,0x0
   0x00000000004012d1 <+122>:   call   rdx
   0x00000000004012d3 <+124>:   mov    edi,0x0
   0x00000000004012d8 <+129>:   call   0x4010e0 <exit@plt>
```

`<+4>`から`<+8>`では`rbp`に現在の`rsp`の値を入れた後，アドレスが減る方向に`0x30`バイトのスペースを確保しています．

`<+80>`から`<+84>`では第２引数（後に`scanf`の結果が入る場所）に`rbp-0x24`をセットし，`<+87>`から`<+94>`では第１引数（`scanf`の方を決める文字列）に`rip+0xde5`の`.rodata`領域から`%u`をセットしています．`<+102>`では実際に`scanf`を呼び出します．入力された値を`<+107>`と`<+110>`で`eax`（`rax`の下位4バイト）に写し，`<+112>`で`rbp+rax*8-0x20`の値を`rdx`に移しています．

最終的に`rdx`は`<+122>`で呼び出されるため，`rbp+rax*8-0x20`を`rbp+0x08`にすればリターンアドレスにたどり着けます．

逆算すると，`rax`=5である必要があるので`scanf`のところで5を入力すれば良いことが分かりました．
