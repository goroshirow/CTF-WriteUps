# I cannot decrypt RSA

## / Overview

$\phi = (p+1)(q+1)$になってしまったRSA

## / Writeup

通常のRSAの暗号化プロセスでは、公開鍵$`e`$から秘密鍵$`d`$を生成する際に、$`\phi_t = (p-1)(q-1)`$を用いて$`ed\equiv 1 \pmod{\phi_t}`$となるように$`d`$選びます。

ですが今回のチャレンジでは$`\phi_f = (p+1)(q+1)`$で$`d`$を計算しています。その結果$`m^{ed} \not\equiv m \pmod{n}`$ となってしまい、復号に失敗しています。

チャレンジを解くにあたって、ユーザには
- $`n=pq`$
- $`e`$
- $`\phi_f = (p+1)(q+1)`$
- $`m^{ed} \pmod{n}`$

の4つが与えられます。ここから$`m`$を復号できればクリアです。

通常のRSAでもそうですが、$`\phi`$が与えられている場合は$`p,q`$を特定できてしまいます。理由は$`\phi_f - n - 1 = p + q`$を用いて

$$x^2 - (\phi_f-n-1)x + n = (x-p)(x-q)$$

と因数分解ができるからです。実際にSageMathで特定してみます。

```py
n = ...省略...
phi = ...省略...
R.<x> = QQ[]
F = factor(x^2 - (phi-n-1)*x + n)
print(F)
```

無事に$`p, q`$の組が求まりました。おかげで本当の$`\phi_t = (p-1)(q-1)`$を計算できます。

今、$`m^{ed} \pmod{n}`$を**公開鍵$`ed`$を使ったRSA暗号**だと考えると、今回は運よく$`gcd(ed, \phi_t) = 1`$ が成立しているため、$`ed`$ の逆元を取ることができて、先に$`d \equiv e^{-1} \pmod{\phi_f}`$を計算することで対応する秘密鍵$`d' \equiv (ed)^{-1} \pmod{\phi_t}`$が作れます。

これで$`(m^{ed})^{d'} \equiv m \pmod{n}`$としてフラグが復号できました。

```py
from Crypto.Util.number import bytes_to_long, long_to_bytes

e = ...省略...
flag = b'...省略...'
p = ...省略...
q = ...省略...

assert p*q == n

d = pow(e, -1, phi)
ed = e*d
inv_ed = pow(ed, -1, (p-1)*(q-1))

m = pow(bytes_to_long(flag), inv_ed, n)

long_to_bytes(m)
```
